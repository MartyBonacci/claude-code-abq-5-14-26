# Claude Code Statusline Setup

This is the statusline you saw in the talk — shows your current directory, git branch, model, effort level, context window usage, rate limits, session time, token burn rate, and your last prompt.

Powered by [`@chongdashu/cc-statusline`](https://www.npmjs.com/package/@chongdashu/cc-statusline).

---

## Quick Install

### Step 1 — Install `jq` (recommended)

Enables richer JSON parsing. Without it, some features fall back to regex.

```bash
# Mac
brew install jq

# Ubuntu / Debian
sudo apt install jq
```

### Step 2 — Generate the statusline script

```bash
npx @chongdashu/cc-statusline install
```

This writes `~/.claude/statusline.sh`.

### Step 3 — Wire it into Claude Code

Add this to `~/.claude/settings.json` (create the file if it doesn't exist):

```json
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh",
    "padding": 0
  }
}
```

If `settings.json` already has content, merge the `statusLine` key into the existing object.

### Step 4 — Restart Claude Code

The statusline appears at the top of every session.

| Icon | What it is |

| 📁 | Current working directory |
| 🌿 | Git branch (+ `[worktree]` if in a git worktree) |
| 🤖 | Active Claude model |
| ⚡ | Effort level (`low` / `medium` / `high`) |
| 🧠 | Context window usage bar + percentage |
| 🚦 | Rate limit usage — 5-hour and 7-day windows |
| ⌛ | Time remaining in current usage session (requires `ccusage`) |
| 📊 | Total tokens used + burn rate in tokens/min (requires `ccusage`) |
| ⚠ | Claude platform incident alert — shows incident title or affected components; hidden when all systems are operational |
| → | Your last prompt, truncated to fit the terminal |

## What's Custom

The script was generated by `cc-statusline` with these features: `directory, git, model, context, usage, session, tokens, burnrate`. Three things you see in the live demo are **not** from the package — they were added by hand after generation:

**⚡ Effort level** — reads `effortLevel` directly from `~/.claude/settings.json` and colors it by urgency (blue → gold → coral as you go low → medium → high).

**👤 Account email prefix** — calls `claude auth status`, caches the result keyed by a fingerprint of your access token so it only re-fetches when you log in or out.

**→ Last prompt** — reads the `transcript_path` from Claude Code's JSON input, finds your most recent user message, and truncates it to fit the terminal width. It's the thing that makes the statusline feel like a "now playing" indicator.

**⚠ Platform status alert** — polls `https://status.claude.com/api/v2/summary.json` every 5 minutes in the background (never blocks). Shows the active incident title in gold/coral/red depending on severity. Disappears entirely when all systems are operational. Requires `curl`.

<details>
<summary>Code to add to <code>~/.claude/statusline.sh</code></summary>

Paste this block somewhere before your render section (e.g. just before the `ccusage` block):

```bash
# ---- claude platform status (background-cached, never blocks) ----
PLATFORM_STATUS_CACHE="/tmp/claude-platform-status.json"
PLATFORM_STATUS_MAX_AGE=300

_refresh_platform_status() {
  curl -sf --max-time 5 "https://status.claude.com/api/v2/summary.json" \
    > "${PLATFORM_STATUS_CACHE}.tmp" 2>/dev/null \
    && mv "${PLATFORM_STATUS_CACHE}.tmp" "$PLATFORM_STATUS_CACHE" 2>/dev/null \
    || rm -f "${PLATFORM_STATUS_CACHE}.tmp" 2>/dev/null
}

if command -v curl >/dev/null 2>&1; then
  if [ ! -f "$PLATFORM_STATUS_CACHE" ]; then
    (_refresh_platform_status) &
  else
    _cache_mod=$(stat -c %Y "$PLATFORM_STATUS_CACHE" 2>/dev/null || stat -f %m "$PLATFORM_STATUS_CACHE" 2>/dev/null || echo 0)
    _now=$(date +%s)
    if [ $(( _now - _cache_mod )) -ge $PLATFORM_STATUS_MAX_AGE ]; then
      (_refresh_platform_status) &
    fi
  fi
fi

platform_status_line=""
if [ -f "$PLATFORM_STATUS_CACHE" ] && [ "$HAS_JQ" -eq 1 ]; then
  _indicator=$(jq -r '.status.indicator // "none"' "$PLATFORM_STATUS_CACHE" 2>/dev/null)
  if [ "$_indicator" != "none" ]; then
    _incident=$(jq -r '[.incidents[] | select(.status != "resolved") | .name] | first // ""' "$PLATFORM_STATUS_CACHE" 2>/dev/null)
    _affected=$(jq -r '[.components[] | select(.status != "operational") | .name] | join(", ")' "$PLATFORM_STATUS_CACHE" 2>/dev/null)
    _msg="${_incident:-${_affected}}"
    [ -z "$_msg" ] && _msg="$_indicator"
    _ps_clr=""
    _ps_rst=""
    if [ "$use_color" -eq 1 ]; then
      case "$_indicator" in
        minor)    _ps_clr="$(printf '\033[38;5;222m')" ;;  # gold
        major)    _ps_clr="$(printf '\033[38;5;203m')" ;;  # coral
        critical) _ps_clr="$(printf '\033[38;5;196m')" ;;  # bright red
      esac
      _ps_rst="$(printf '\033[0m')"
    fi
    platform_status_line="⚠ ${_ps_clr}${_msg}${_ps_rst}"
  fi
fi
```

Then add this just before your `# LINE 3` / session time block to append the alert to your metrics line:

```bash
if [ -n "$platform_status_line" ]; then
  [ -n "$line2" ] && line2="${line2}  ${platform_status_line}" || line2="$platform_status_line"
fi
```

## Customizing

The generated `~/.claude/statusline.sh` is plain bash — edit it directly to change colors, remove sections, or add your own data sources. The color palette uses 256-color ANSI codes; look for the `*_color()` functions near the top.

To regenerate with different options:

```bash
npx @chongdashu/cc-statusline install --theme minimal
```

Run `npx @chongdashu/cc-statusline --help` to see all available themes and flags.
